## 前言

过去几周，我一直在使用 MiMoCode 来搭建和维护这个博客。从最初的主题重构、部署流程优化，到加密小说栏目的实现，几乎所有工作都是在这个 AI 助手的协助下完成的。

但真正让我感兴趣的，不只是它能帮我写代码——更是它背后的**运作方式**。为什么它能记住我之前做过的事情？为什么它在修改文件前会询问权限？为什么它能同时处理多个任务？

这篇文章，是我对 MiMoCode 操作逻辑的一次深度梳理。

## 第一层：多代理协作

MiMoCode 不是"一个 AI 在回答你"，而是一个**代理舰队**（agent fleet）。

最顶层的是**主代理**（primary agent），负责与你直接对话，理解你的需求，决定下一步做什么。但主代理并不孤单——它可以根据需要派遣**子代理**（subagent）去执行具体的子任务。

子代理有不同的专长：
- **explore** — 只读的代码库探索者，快速搜索和定位代码
- **general** — 通用多步骤工作者，处理复杂的分析或实现任务

这种架构的好处是**并行化**。当你提出一个复杂需求时，主代理可以同时派出多个子代理去研究不同的方面，然后汇总结果。就像你是一个项目经理，手下有多个研究员同时为你工作。

## 第二层：权限模型

MiMoCode 的权限系统是我见过的最精心设计的三层模型：

```
agent.permission → 用户配置 → agent.hardPermission
```

每一层都可以覆盖上一层，但**最后一层永远胜出**。这意味着：

1. **agent.permission** — 代理自身的能力限制（比如 explore 子代理只能读文件，不能写）
2. **用户配置** — 你可以在设置中自定义允许或拒绝某些操作
3. **hardPermission** — 代理的硬性规则，**无法被用户配置覆盖**

这就是为什么"计划模式"（plan mode）如此安全——它的 `hardPermission` 禁止了所有写操作（除了计划文件），即使用户配置了 `"*": "allow"`，也无法绕过这个限制。权限是**编码在数据中的安全**，而不是依赖代码逻辑的特殊处理。

每次工具调用都会经过 `runtimePermission()` 评估，决定是允许、询问还是拒绝。对于敏感文件（如 `.env`），读取也需要确认。

## 第三层：持久化记忆

这是 MiMoCode 最强大的特性之一——它拥有**跨会话的持久化记忆**。

记忆系统基于文件存储，分为四种类型：

- **user** — 用户偏好和个人信息
- **feedback** — 用户对之前操作的反馈
- **project** — 项目级别的架构决策和规则
- **reference** — 可复用的技术参考

这些记忆以 Markdown 文件的形式存储在 `~/.claude/projects/<slug>/memory/` 目录下，通过 BM25 全文搜索索引。当你开始新会话时，系统会自动加载相关的记忆，让 AI 了解之前的上下文。

除了长期记忆，还有**会话检查点**（checkpoint）——定期保存当前会话的结构化状态，包括活跃意图、任务进度、文件变更等。即使会话被压缩或中断，也能从检查点恢复。

这意味着：你不需要每次重复解释项目的背景。MiMoCode 会记住你的技术栈偏好、项目的架构决策，甚至你之前犯过的错误。

## 第四层：任务追踪

MiMoCode 内置了层级化的任务管理系统。任务用 ID 标识（如 T1、T1.1、T1.2），支持状态流转：

```
open ⇄ in_progress → blocked → open
                  ↘ done
                  ↘ abandoned
```

当你提出一个复杂的多步骤需求时，主代理会自动创建子任务，分配给子代理执行。每个子代理完成任务后，其发现会自动集成回主任务的进度中。

这让我想起项目管理中的"工作分解结构"（WBS）——大任务被拆分成小的、可执行的子任务，各自独立推进，最终汇总完成。

## 第五层：会话生命周期

一次 MiMoCode 会话的内部流程远比"你问我答"复杂：

1. **classify / instruction / goal** — 意图提取：理解你想做什么
2. **checkpoint** — 定期快照：保存会话状态
3. **compaction / overflow / prune** — 上下文管理：当对话过长时，压缩和精简历史消息
4. **summary / title** — 会话结束时生成摘要和标题
5. **distill / dream** — 后台强化长期记忆

其中**压缩**（compaction）机制特别重要。当对话接近上下文窗口限制时，系统会自动总结和丢弃旧消息，而不是简单截断。这意味着你可以进行很长的对话，而不必担心"前面说的被忘了"。

## 第六层：技能与扩展

MiMoCode 的能力可以通过两种方式扩展：

- **Skills**（技能）— Markdown 文件（`SKILL.md`），注入特定领域的知识和工作流。比如处理 PDF、Excel、学术搜索等。技能不改变工具集，而是改变**行为指导**。
- **MCP servers**（模型上下文协议）— 外部工具/资源服务器，通过 JSON-RPC 协议集成。这扩展了**工具集**本身。

两者的区别很清晰：技能教 AI "怎么做"，MCP 给 AI "新工具"。

## 总结

回顾这几周的使用，MiMoCode 让我印象最深的不是某个单一功能，而是这些层次的**协同工作**：

1. **多代理并行** — 让复杂任务可以被拆分和并行处理
2. **三层权限** — 安全不是事后补丁，而是架构设计的一部分
3. **持久化记忆** — 跨会话的连续性，让 AI 真正"了解"你的项目
4. **任务追踪** — 结构化的进度管理，避免复杂任务失控
5. **会话生命周期** — 自动化的上下文管理和记忆强化
6. **技能扩展** — 灵活的领域知识注入

这些层次组合在一起，构成了一个既能高效协作、又值得信赖的 AI 编程助手。它不只是回答问题——它在**管理理解你、记住你、保护你**的过程中，逐步建立起真正的协作关系。

折腾本身，就是乐趣的一部分。
